# Architecture

## Layout

```text
src/
├── main.ts                 bootstrapApplication(App, appConfig)
├── environments/           GENERATED by load-env.js (gitignored)
└── app/
    ├── app.ts / app.config.ts / app.routes.ts   shell, providers, lazy feature routes
    ├── shared/                                   plumbing every feature needs (see capability map)
    │   ├── enums/          StorageEnum
    │   ├── helpers/        isUsableBearerToken
    │   ├── interceptors/   authInterceptor (functional)
    │   ├── interfaces/     response envelopes
    │   ├── providers/      provideAppHttpClient()
    │   └── services/       StorageService
    └── modules/
        └── template/       reference feature module (cloned by the generator)
```

Screaming layout: each folder under `modules/` is a business feature, and everything the feature
needs lives inside it. `shared/` only holds what every feature needs; feature code never imports
another feature.

## Module anatomy

```text
modules/<feature>/
├── <feature>.routes.ts     export const <Feature>Routes: Routes   (lazy-loaded from app.routes.ts)
├── pages/                  containers: inject services, own signals, loading/error state
├── components/             presentational: input()/output() only
├── services/               HTTP: `${environment.apiUrl}/<resource>`
├── interfaces/             request/response types
└── constants/
```

Each feature exports a `Routes` array named `<Feature>Routes` and is mounted with `loadChildren`.
This is the same shape a Native Federation remote exposes, which keeps
[a later migration](migrate-to-native-federation.md) mechanical.

### Container-presentational

- Pages (containers) are the only place that injects feature services or the router, and they own
  the loading and error UI.
- Components receive data through `input()`/`input.required()` and emit intent through `output()`.
  They have no services and are trivially testable with `setInput()`.

### Angular rules (enforced in review)

- `standalone: true`, `changeDetection: ChangeDetectionStrategy.OnPush` in every component.
- Zoneless change detection (`provideZonelessChangeDetection()`): state lives in signals; do not
  add `zone.js` or rely on zone-triggered change detection.
- Built-in control flow `@if` / `@for (...; track ...)` / `@switch`; `@defer` for heavy lazy UI.
- `inject()` for DI, no constructor parameters.
- Signals for state (`signal`, `computed`, `effect`), `update`/`set` never `mutate`.
- Functional interceptors/guards/resolvers (`HttpInterceptorFn`, `CanActivateFn`).
- External templates (`templateUrl`) inside feature modules: the generator protects
  `templateUrl`, but an inline `template:` is fine too.

## HTTP

`app.config.ts` registers `provideAppHttpClient()` (`src/app/shared/providers/http.providers.ts`),
the only HttpClient of the app, with the functional `authInterceptor` (adds
`Authorization: Bearer <token>` from `StorageService` when a usable token exists and the caller did
not set one). New interceptors (error handling, loader, refresh) go into that list.

## Creating a module

```bash
bun run generate:module -- --name=user-profile            # src/app/modules/user-profile
```

The generator (`scripts/generate-module.js`, tested in `scripts/generate-module.test.js`) copies
`modules/template`, renames files and contents (`template` → kebab, `Template` → Pascal,
`TEMPLATE_` → CONSTANT) and prints the lazy route to add to `app.routes.ts`. Then adjust the
endpoint path and the interfaces.

Improvements to the reference module are made in `modules/template`, so every future module
inherits them.
