# Architecture

## Layout

```text
src/
├── main.ts                 standalone SPA entry: import('./bootstrap')
├── main.federation.ts      federation entry: initFederation() -> import('./bootstrap')
├── bootstrap.ts            bootstrapApplication(App, appConfig)
├── environments/           GENERATED by load-env.js (gitignored)
└── app/
    ├── app.ts / app.config.ts / app.routes.ts   standalone-dev shell (never runs in the host)
    ├── core/                                     ports + safe local defaults (no host code)
    │   ├── app-locale.ts          provideAppLocale() + ES_EC_LOCALE preset (es-EC + USD)
    │   ├── auth-token.ts          AUTH_TOKEN_PROVIDER
    │   ├── key-value-storage.ts   KeyValueStorage + LocalStorageKeyValueStorage
    │   ├── notifier.ts            Notifier + ConsoleNotifier
    │   ├── permission-checker.ts  PermissionChecker + AllowAllPermissionChecker
    │   └── app-core.providers.ts  provideAppCore()
    ├── integrations/
    │   └── neocore/              EVERYTHING host-specific, bound by provideNeocoreHost()
    ├── shared/                   plumbing every MF needs (see capability map)
    │   ├── guards/         permissionGuard (PermissionChecker + Notifier)
    │   ├── helpers/        isUsableBearerToken, toUserMessage
    │   ├── interceptors/   generic authInterceptor (Bearer from AUTH_TOKEN_PROVIDER)
    │   ├── interfaces/     response envelopes
    │   ├── providers/      provideAppHttpClient() + APP_HTTP_INTERCEPTORS
    │   └── services/       LoadingTrackerService
    └── modules/
        └── template/       reference feature module (cloned by the generator)
```

Dependency direction: `modules` and `shared` depend on `core`; `integrations/neocore` depends on
both; NOTHING imports `integrations/` from `core`, `shared` or `modules`. Removing the integration is
deleting that folder and the `provideNeocoreHost()` calls.

Screaming layout: each folder under `modules/` is a business feature, and everything the feature
needs lives inside it. `shared/` only holds what every feature needs; feature code never imports
another feature.

## Module anatomy

```text
modules/<feature>/
├── <feature>.routes.ts     export const <Feature>Routes: Routes   (exposed entry)
├── pages/                  containers: inject services, own signals, report through Notifier
├── components/             presentational: input()/output() only
├── services/               HTTP: `${environment.apiUrl}/<module path constant>`
├── interfaces/             request/response types
├── enums/                  permission resource/actions
└── constants/              page size, API path, ...
```

### Container-presentational

- Pages (containers) are the only place that injects feature services, `Notifier`,
  `LoadingTrackerService` or the router.
- Components receive data through `input()`/`input.required()` and emit intent through `output()`.
  They have no services and are trivially testable with `setInput()`.

### Angular rules (enforced in review)

- `standalone: true`, `changeDetection: ChangeDetectionStrategy.OnPush` in every component.
- Built-in control flow `@if` / `@for (...; track ...)` / `@switch`; `@defer` for heavy lazy UI.
- `inject()` for DI, no constructor parameters.
- Signals for state (`signal`, `computed`, `effect`), `update`/`set` never `mutate`.
- Functional interceptors/guards/resolvers (`HttpInterceptorFn`, `CanActivateFn`).
- External templates (`templateUrl`) inside feature modules: the generator protects
  `templateUrl`, but an inline `template:` is fine too.

### Permissions and gateway

The app asks the `PermissionChecker` port (allow-all by default; `provideNeocoreHost()` reads the
host's `ROLE_PERMISSION`/`PERMISSION` payloads). Resource and actions live in the feature's
`enums/*-action.enum.ts` and are passed to `permissionGuard(resource, action)`.

Only with `provideNeocoreHost()`: every request to the NEOCORE gateway carries
`x-api-key: <resource>:<action>` built with `buildPermissionHeaders()`, and the microservice path
prefix comes from `MsPrefixEnum`. Both live in `src/app/integrations/neocore/http/`; generic code
builds its URL from `environment.apiUrl` plus a module-local path constant.

## Creating a module

```bash
bun run generate:module -- --name=user-profile            # src/app/modules/user-profile
bun run generate:module -- --name=user-profile --expose   # + federation.config.mjs + tsconfig.federation.json
```

The generator (`scripts/generate-module.js`, tested in `scripts/generate-module.test.js`) copies
`modules/template`, renames files and contents (`template` → kebab, `Template` → Pascal,
`TEMPLATE_` → CONSTANT) and prints the lazy route to add to `app.routes.ts`. Then adjust the
permission resource, the endpoint path and the interfaces.

Improvements to the reference module are made in `modules/template` of this repo, so every future
module (and every fork after a merge) inherits them.
